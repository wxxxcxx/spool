# 配置、脚本与新格式恢复怎样形成初始意图

Id: 09
Type: grilling

Assignee: none
Parent: [Spool 声明式状态模型与迁移边界](../map.md)
Blocked by: 05, 07

## Question

本轮无需旧兼容：定义配置默认、显式命令、脚本、外部接纳、新格式启动恢复的优先级；哪些首切片意图持久化，哪些仅运行期；启动身份/拓扑不明时怎样导入，不恢复旧在途操作。

## Answer

输入来源和保存/导入协议三方支持，按用户授权接受。首切片实际自动恢复范围与身份可实现性另票明确，不以“确认身份”四字掩盖实现缺口。

- 布局字段记录“继承配置”或“显式覆盖”；等值显式赋值仍是覆盖，不能按数值相等推断来源。清除覆盖是显式转移。
- 配置提供可继承默认；已验证启动导入低于本次会话显式编辑；命令、脚本显式调用、已接纳外部调整以领域接纳序最新胜，不以AX通知时间或来源固定等级决定。
- hot reload只更新仍继承的布局字段；规则资格、ignore和原生写保护是另一维度，显式列宽不能绕过资格政策。Lua仍走worker，不能改在主线程同步跑handler。
- 导入只在启动窗口内使用冻结候选集；字段/结构修改版本必须在提交时再次核验，迟到候选不能覆盖本会话新编辑。未知对象延迟，确定不匹配或窗口到期则退出自动恢复，不搬到活动Space、不为恢复切Space。
- 新格式只保存原始意图、来源与必要候选绑定信息；不保存Observed、有效目标、约束缓存、动画、请求/重试进度、全局激活状态。候选不是原生拓扑事实。
- 已通过领域校验的意图可在native暂不可写或暂缺观测时保存；不得因失败观察清空条目。尚未验证的启动候选与当前有效意图分开。
- 在一致revision捕获快照，后台单写者/提交版本门禁阻止旧任务覆盖新文件；同目录临时文件、同步及原子替换后才报告saved revision，失败保留dirty状态。accepted不保证durable，旧保存成功不意味着新状态已保存。
- 未识别旧格式或损坏文件可忽略并诊断，不迁移、不伪报恢复成功。本轮不执行本机文件删除。

## Votes

- import_domain：协议支持；倾向首片仅宽度与最小关联，不强行恢复旧分组。
- import_platform：协议支持；当前凭据不足以保证跨daemon同一窗口，需单独解决自动绑定范围。
- import_testing：协议支持；强调字段来源、结构revision、候选隔离和保存不回退。
