# 来源不明的焦点竞争是否终止旧激活意图

Id: 13
Type: grilling

Parent: [Spool 声明式状态模型与迁移边界](../map.md)
Blocked by: 05, 06

## Question

已请求聚焦A，随后确认实际焦点稳定在B，却无法可靠识别人类来源：保留A为静止blocked等待明确新输入，还是终止A的激活意图并记录外部让权？两者都停止自动抢焦点且不把B算A完成。

## Answer

三位焦点专项专家一致选择外部让权，按用户授权接受。这是对证据票初步分歧的专项澄清，不掩盖原先意见。

请求A后，原生新鲜读回与稳定复验确认焦点B，且排除原生过渡、旧采样和自身请求链关联时，终止A的Session激活意图，记录外部让权且来源未知；不算A成功，不伪造“用户命令聚焦B”。A的请求记录和每Space偏好可保留，但旧激活目标不得因环境恢复自动复活。

B可以是不在Spool跟踪范围的原生窗口，但前台应用及焦点窗口证据必须一致且身份有效。unknown/unresolved、只知前台应用、单条通知、短暂过渡均不足以让权；这些情况保留A为静止blocked并有限重验。候选提交前再核验当前意图版本，期间新C不得被旧候选终止。

语义级一次激活尝试可包含必要的activate/raise/focus步骤，不能无限跨帧续写。稳定B成立后剩余自动竞争预算为零。此前遇到明确暂时失败是否允许一次额外尝试，另见 [稳定竞争成立前是否允许焦点重试](15-focus-retry.md)。

## Votes

- focus_domain：选择让权；未解析与稳定B分开，终态不可复活。
- focus_platform：选择让权；读回必须在请求后，跨过确认窗口并复验，不能误用请求前B。
- focus_interaction：选择让权；保留未实现历史和Space偏好，不把事实说成用户来源。

## Acceptance

A之后稳定B使A让权；仅unknown不让权；旧请求造成B先按迟到效果处理；候选采样期间新C不被终止；让权后资格变化不再激活A。
