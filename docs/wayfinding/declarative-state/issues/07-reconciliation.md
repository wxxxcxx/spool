# 最新意图的执行资格、重试和回执如何协调

## Question

不可见 Space、原生过渡、AX 不可用时如何接纳合法状态？意图代次、在途尝试、迟到结果、重试触发/预算和命令回执如何分离？确定可实现的有界默认策略及诊断模型。

## Answer

共同协议三方支持，按用户授权采用。具体重试数字拆入独立参数票，焦点另票，不把几何预算套到所有效果。

- 已知有效对象的合法布局编辑立即接纳，返回相关领域revision；可见性、AX、原生过渡是效果资格，不作为一般领域编辑禁令。未知目标身份、非法结构、会话停止接纳仍可拒绝。
- 同一次转移覆盖目标归属、各strip与相关引用的不变量，先校验后原子提交。平台失败不回滚已接纳意图。
- 每个尝试关联incarnation、相关领域revision、语义执行上下文和attempt token，发出前再次验证。上下文指影响资格/约束的真实变化，不是采样generation、通知计数或时间戳。
- 仅协调最新状态。迟到结果不能完成新请求或恢复旧意图，但新鲜、身份有效的现实副作用仍要观察；旧采样不能覆盖更新观察，新鲜度不确定则重读。
- 同一目标/上下文有限串行尝试，未知冲突立即停写，不为耗完预算继续写。实际开始一轮调整即占一次预算，整段正常动画及终点共用该次，中途失败也计入；资格拒绝不扣预算，正常中间帧不逐帧扣次。动画有界及失败停流规则见 [首个完整迁移切片及后续次序怎样验收](10-migration.md)，用户确认的计数口径见 [动画在终点前失败如何计入尝试预算](19-animation-budget.md)。
- 纯时间、同值命令、等值回声与短暂上下文往返不补充预算。相关意图实质变化、可信约束变化、去抖去重后的资格恢复或显式重试才能开启受控新轮次。
- 耗尽后停止该目标专用写重试/轮询，保留blocked原因与唤醒条件；全局被动事件和正常生命周期审计继续。新观察已达到目标可直接确认，不要求额外写入。
- 接纳、原生实现、持久化是三个独立回执维度；保存回执绑定具体快照revision。已被替代不等于失败，受限实现不等于原意图精确满足。
- 约束描述与执行进度分别表达，避免把受限且blocked强塞成一个含混状态。请求可有invalidated/superseded终态；诊断暴露原意图、有效目标、观测差异、证据来源和当前阻塞。
- create/delete Space是显式操作实例协调协议，绑定操作ID、前置拓扑、目标与结果证据；非幂等效果结果未知时只观察，禁止盲重放。它仍是显式状态驱动，不是假造拓扑或放弃声明式的通道。

## Votes

- execution_domain：共同协议支持；三次含首次，约束/执行进度需正交，不主张无依据锁定观察间隔。
- execution_platform：共同协议支持；三次含首次，候选观察点250ms/1s/5s；焦点不套三次写预算。
- execution_testing：共同协议支持；建议首次后额外三次，明确计数口径；静止不等于停止全局观察。

历史计数差异是2:1，未按多数票决定；最终用户裁决见 [几何重试与被动确认采用什么预算](14-retry-budget.md)。
