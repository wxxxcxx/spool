# 改宽后保持窗口可见

## 复现与修复

1024宽的显示器上，第二列窗口起点为400，初始宽400。将列宽设为768后，旧路径仍保留x=400，导致右侧越界144；回归要求x=256、右侧恰好为1024，旧代码失败。

原因是声明式列宽接纳路径更新宽度后，没有发出已有的EnsureVisibleMarker。现于成功接纳可见Space的改宽后请求可见性调整，布局系统先计算新的尺寸和逻辑位置，再按越界距离平移strip。原有转场保护、几何预算拒绝和原生执行门禁保留。后台Space不发此请求；浮动窗口继续走其原有几何路径。

回归覆盖逐档加宽、直接窗口设宽、按Space列序号设宽、尚未越界时不平移，以及宽于屏幕时保留宽度并对齐左边。沿用已有后台接纳与原生写入隔离测试。

## 审查

规范：复用现有ECS标记与布局协调，无新增直接FFI或额外聚焦。规格：只调整必要的滚动距离，不把扩宽替换为缩窄窗口。代码审查未发现阻塞项。

验证：1231项workspace测试通过、0失败、2项忽略；严格Clippy、格式检查、无默认特性编译与debug构建通过。

原生视觉复验仍需加载新版daemon；mock结果不能证明当前运行中的旧进程已修复。
