# 动画在终点前失败如何计入尝试预算

## Question

正常动画在最终目标提交前某个中间写失败：初始推进是否已经占用一次协调预算，还是后续第一次直接终点提交才计第一次？

## Votes

- migration_architecture：动画开始即预占一次目标推进预算，中途失败也占一次；防止失败初试免费。
- migration_testing：预算仅计终点提交，中途失败不虚扣；动画另有有限边界且不允许重播。
- migration_platform：要求中间帧不逐帧扣、失败停流、后续直接终点计数，未明确预占口径。

## Answer

用户在逐项解释后明确同意：一次调整开始执行后，即使动画中途失败，也计入一次尝试。此为用户裁决，历史专家分歧保留在Votes中。

- 在执行资格通过、实际开始该轮原生调整时，以尝试token占用一次预算；仅排队、派生、资格阻塞或尚未发生原生写入不计次数。
- 同一轮正常动画的全部中间帧和最终目标提交共用该次尝试；不逐帧扣次数，也不在到达终点时重复扣一次。观察已经到位时无需为了计数再发写入。
- 中途失败立即停止该动画流，已占用的一次不返还。若仍有预算且符合执行资格，后续尝试直接提交最新最终目标，不重播动画。
- 含初次共3次的上限下，初次动画中途失败后最多剩2次尝试；每次后续实际执行也消耗一次。最终仍失败保留意图与阻塞原因，不无限重新开动画或因纯时间补次数。
- 任何帧仍受身份、当前版本和冲突门禁约束，正常动画必须有界；这不改变新意图替代旧目标、未知冲突停写和原生读回确认的规则。

## Acceptance

600到900的正常动画无论多少中间帧都只占一次；在700写入失败后后续动画帧停止，预算剩2次；后续许可尝试直接900，每轮各计一次；从未通过执行资格时不扣预算；终点确认不双重扣费。
