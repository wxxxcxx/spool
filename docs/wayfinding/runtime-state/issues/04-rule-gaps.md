## Question

ADR 0010 把跨会话偏好交给规则表达，而现有规则词汇（`src/config.rs:783` 的 `WindowParams`）只覆盖：`floating`、`track`、`index`、`width`（比例）、`grid`、paddings、`dont_focus`、`border_radius`、`bindings_passthrough`。重建表里因此有缺口：运行时拉宽的列、手调的 stack 高度、精确浮动位置、窗口的 Space、每 Space 焦点、栈/tab 成员。本票是这些缺口的**收集处**：每加一个字段就开一张自己的子票，不在本票内实现。

## 决策沿用（ADR 0010，已确认）

- 规则按 `bundle_id` / 标题等匹配，规则字段可以一张票一张票加。
- 没有规则表达的偏好**不跨会话保留**（兜底：观测 → 默认），这条丢失是接受的。

## 候选字段（按需，未裁决优先级）

| 字段 | 表达什么 | 兜底（无规则时） |
|---|---|---|
| 列宽（绝对值或比例） | 运行时手拉的列宽 | 观测：新列一次性采纳接纳时宽度 |
| stack 高度比例 | 手调的高度 | 等分 |
| 浮动位置（精确 frame） | 拖到的位置 | `grid`，否则窗口自身启动位置 |
| Space 归属 | 窗口该去哪个 Space | 原生观测 |
| 焦点偏好 | 某 Space 启动时聚焦谁 | 当前聚焦窗口 / 第一个可用 |
| 栈/tab 成员与顺序 | 哪些窗口叠在一起 | `index` 影响的发现顺序 |

## 状态（2026-09-16）：用户明确暂缓

用户看过这张损失清单后决定**都不先做**。本票保持 `open` 作为待办收集处；任何时候要做，按"用户实际痛感"排序的候选是：① 栈/tab 组合与顺序（Spool 独有概念，且落盘时代也恢复不了）；② 手调的列宽/高度被重置；③ 每 Space 焦点记忆；④ 浮动精确位置与 Space 归属（多数由 macOS 自身恢复）。

## 边界

- 本票不实现任何字段；每个字段需要自己的子票（含匹配语义、优先级、与 `floating`/`width` 等既有字段的交互、以及"规则与运行时编辑冲突时谁赢"）。
- 不恢复"逐窗口实例"记忆：规则必须按应用/窗口特征表达，不能按窗口编号。
